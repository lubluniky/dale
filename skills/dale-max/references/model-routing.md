# Optional model routing

Inherit the user-selected model and reasoning by default. Use an explicit route
only when the user requests one or requests an economy profile. Check current
supported model, effort, and context combinations in the live tool schema.
Do not hard-code a generation, maximum effort, or price/quality ranking.

For an economy profile, use the user’s mapping or current verified model guidance
and explain the workload reason. If no reliable mapping is available, inherit
settings and disclose that economy routing was not established. If an explicit
route is unavailable, report the mismatch rather than silently substituting.
Escalate for a concrete bottleneck or failed approach; repair an unclear work
contract before spending more reasoning. Follow live rules for model overrides.
